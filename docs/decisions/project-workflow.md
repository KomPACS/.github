# Project workflow

Decided 2026-10-20. Rules: `CONTRIBUTING.md`.

## Why

- Kanban pull, no sprints: 2–3 part-time people cannot forecast sprint capacity. We talk daily, so no fixed sync.
- Goals, not dated milestones: GitHub milestones are per repo and cannot span the org. Goal names stay valid when dates slip.
- No Priority field: Goal plus manual order is enough. A second priority axis drifts.
- Issue types, not kind labels: they work in every repo and in Project filters. Labels hold only what the repo and type cannot show.
- Plain issue titles: the type field already holds the kind. Conventional Commits stay on PRs and commits.
- Claude updates the board: with daily chat, a hand-kept board goes stale in about 2 weeks. Then nobody trusts it.
